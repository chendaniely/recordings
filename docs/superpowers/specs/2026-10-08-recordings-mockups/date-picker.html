Design notes

What it shows

  • One button, one chip (§12.6a). The button in the list header reads Any date, a preset's name (Last 7 days, 2026W1), a whole month (October 2026), a year (2026), Today, or the range (Oct 1 – 15). The active range also sits in the chip row above the list (Oct 1–15 ×), where every active filter lives, and × removes it.
  • Presets apply at once and close the popover. Calendar clicks are a draft until Apply. Esc or a click outside discards the draft. Clear empties the draft and leaves the popover open.
  • The footer reads live: "Oct 1 – 15 · 9 recordings". It also previews whatever is under the pointer, either a preset ("Last 7 days · Oct 2 – 8 · 7 recordings") or the range a second click would make.
  • Picking: the first click selects that day, a second click makes the range, and a third starts again. Shift-click extends the range. A hand-picked range that matches a preset highlights that preset, so Oct 2 – 8 lights up Last 7 days.
  • The band: solid blue ends, a blue tint between them, and rounded caps where a week or month wraps, so it reads as one band. Today has a ring in the muted text colour, so it isn't mistaken for the blue focus ring. There is no orange in the control (§12.6). Orange appears only on the active page in the top bar.
  • Dots mark days with recordings. A dot turns white on a solid end, as the spec asks, and blue inside the tinted band, where white would vanish.
  • Layout: two months, with the current month on the right, and no paging into the future. Days from other months are hidden, so a day never shows twice in the band. There are always six week rows, so the popover doesn't change size as you page. Weeks start on Monday.
  • The month caption opens a grid of months and years. It lists only years with recordings, plus this one, so the demo's 1933–1970 recordings are two clicks away. Each month is shaded by its count on a single blue scale (Insights' heatmap scale, §12.6b) and outlined if it's showing now. Picking a month jumps the calendar there. Esc goes back to the days.
  • On a phone: a bottom sheet with one month, 44 px day targets, presets as a scrolling row of chips (terms after a divider) and the same footer, with a full-width Apply.
  • Ranges use local dates from recorded_at and its own offset (§12.6a), so a 23:30 −07:00 recording stays on its own day. The mockup fixes "today" at Thu Oct 8, 2026. It has 40 invented recordings over 14 months, plus the four historical demo recordings.
  • Future days in the current month are muted but can be picked, so "Oct 1 – 15" works as in the spec. An empty result suggests wider ranges with counts (§12.6a, empty states).

Building it

  • The real build uses shadcn's Calendar (react-day-picker) in range mode with a custom day style: mode="range", numberOfMonths={2} (1 on a phone), weekStartsOn={1}, showOutsideDays={false}, endMonth set to this month, a hasRecordings modifier for the dots, and a custom DayButton for the band, ring and dot. Wrap it in shadcn's Popover on desktop and its Drawer on a phone.
  • Check the current docs first (§12.6a). On 2026-10-08, react-day-picker's own docs showed a v10 that imports from @daypicker/react, while shadcn's Calendar still imports react-day-picker. Confirm which version the shadcn registry pins before writing the custom day.
  • Its built-in keys clash with the spec. DayPicker uses Shift+arrow to move by month (←→) or by year (↑↓). The spec wants Shift to extend the range, as this mockup does, so the build needs an onDayKeyDown override. PgUp and PgDn already move by month.
  • The month/year grid is custom. captionLayout="dropdown" gives two native selects with no counts, so the grid replaces MonthCaption.
  • DayPicker's default range clicks may handle a third click differently from "start again". Check this against the docs.

Open questions for Dan

  • Should the list preview the draft live behind the popover, or change only on Apply, as here?
  • The button and the chip both show the range, as the spec says. Keep both, or let the active button act as the chip?
  • Week start: the spec says "the same day as in Insights", but §12.6b doesn't name a day. This mockup uses Monday. Should it be a config value?
  • The shape of [calendar] terms isn't specified anywhere. Here is a proposal: 
    [calendar]
week_start = "monday"     # proposed
terms = [
  { name = "2026W1", start = 2026-09-08, end = 2026-12-18 },
  { name = "2025W2", start = 2026-01-05, end = 2026-04-17 },
  { name = "2025W1", start = 2025-09-02, end = 2025-12-19 },
]
  • Dark mode dot: the spec says the dot turns white on selected days. In dark mode the end is light blue (#6CA6D9), where white is only about 2.3:1, so the mockup uses the day's dark text colour there. Please confirm.
  • In a saved link or hash route, should Last 7 days keep rolling, or freeze to its dates?
